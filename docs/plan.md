| 항목 | 내용 |
|---|---|
| 한 줄 정의 | 생년월일시 하나로 **"오늘 내 돈 씀씀이"**를 점수·시간대·행동 지시로 알려주는 한국형 금전 사주 미니앱 |
| 무료로 주는 것 | 오늘의 지갑 점수(0~100), 한 줄 직설 코멘트, 소비 방어력, 재물 기운 등급, 충동구매 위험 시간대 |

**왜 이 앱인가(요약)**: 앱인토스에서 광고 단가(eCPM)가 가장 높은 축이 운세·사주·타로류이고, 그중에서도 "돈"으로 축을 좁히면 ①토스 사용자 맥락(돈 쓰러 오는 앱)과 정확히 겹치고 ②결과 직전 집중도가 높아 리워드 광고 완주율이 올라가며 ③매일 갱신되는 콘텐츠라 재방문율(추천 미니앱 선정의 핵심 지표)을 만들기 쉽다. 대신 "띠별 총운"과의 차별은 **돈 하나에 대한 구체적 행동 지시**에서 만든다.

## 1. 서비스 개요 & 차별화 포인트

### 1.1 한 줄 정의 & 포지셔닝

> **"오늘 카드를 꺼내도 되는 날인지, 3초 안에 알려주는 지갑 전용 사주."**

기존 운세 앱은 `띠별/별자리 총운 → 애매한 형용사`로 끝난다. 이 앱은 **입력값(생년월일시) × 오늘 일진**으로 계산한 결과를 **돈에 관한 행동 지시**로 번역한다.

- 나쁜 예: "오늘은 인내가 필요한 하루입니다."
- 좋은 예: "오늘은 카드 내려놔라. 21시 넘어 배달앱 켜면 그게 그달 카드값이다."

### 1.2 타겟 & 페르소나

| 페르소나 | 규모 감각 | 이 사람의 돈 고민 | 이 앱이 주는 것 |
|---|---|---|---|
| **A. 충동형 20~30대** (카드값·구독·배달) | 토스 MAU의 최대 축 | "이번 달 또 카드값 터졌다", "쿠팡 열었다 하면 산다" | 충동구매 위험 시간대, 피해야 할 지출 항목, 지갑 점수 하락 경고 |
| **B. 재테크 관심 30~40대** | 중간 | "지금 들어가도 되나", "이번 주 용돈 남나" | 재물 기운 등급, 매수 '기운' 표시(투자 권유 아님), 재물 부스터 행동 |
| **C. 재미 소비 40~50대** | 안정적 | "로또 한 장", "오늘 뭐 사면 좋대" | 행운 번호, 럭키 컬러·아이템, 친구 궁합 비교 |

- **1차 타겟**: A (재방문·광고 완주를 만드는 층) → 유입은 A, 매출은 B·C가 만드는 구조.
- **연령 정책**: 만 19세 미만에게는 "행운 번호"를 노출하되 **구매 권유 문구·복권 이미지·당첨 확률 표현을 전면 금지**한다(3.4 참조).

### 1.3 핵심 가치 3가지

1. **구체성 (Specificity)** — 점수만 주지 않고 "몇 시에, 무엇을, 하지 마라"까지 준다. 모든 결과는 행동 문장으로 끝난다.
2. **근거 노출 (Show the math)** — 결과 하단에 `丁火 일간 × 戊戌 일진 · 상관(傷官) · 설기(泄氣)`처럼 계산 근거 한 줄을 노출한다. "아무 말"이 아니라 "규칙이 있는 말"로 신뢰를 만든다.
3. **무마찰 (Zero friction)** — 로그인 없이, 3탭으로, 2초 안에 결과. 재방문은 원탭.

### 1.4 경쟁 비교

| 비교 대상 | 그들의 방식 | 약점 | 이 앱의 차이 |
|---|---|---|---|
| 포털 띠별 운세 | 12개 띠 × 총운/연애/금전 | 개인화 0, 매일 같은 말 | 생년월일시 기반 60갑자 × 십성 = 개인별 조합 |
| 타로 미니앱 | 카드 뽑기 랜덤 | 결과가 랜덤이라 신뢰 축적 안 됨, 돈 축 없음 | 같은 날·같은 사람 = 같은 결과(결정적), 축은 오직 돈 |
| 토스 내 금융 기능(머니·카드) | 실제 자산·소비 데이터 | 미래/기분을 말해주지 않음, 권한·동의 장벽 | 데이터 권한 0, 감정적 동기로 재방문 |
| 사주 유료 앱(신점·만세력) | 3~5만 원 고가 상담 | 결제 장벽, 1회성 | 1,100~3,300원 소액, 매일 무료 |
| **이 앱** | 일진 × 십성 × 오행을 돈 행동으로 번역 | — | **"돈 전용" + "근거 노출" + "무로그인"** |

### 1.5 앱 이름 후보 5개

| # | 이름 | 뉘앙스 | 장점 | 리스크 | 판정 |
|---|---|---|---|---|---|
| 1 | **오늘 지갑운** | 직관·검색어 결합 | "지갑운" 검색 유입 흡수, 기능이 이름에 그대로 | 개성 약함 | **추천** |
| 2 | **지갑 사정** | 구어체·위트 | 공유하고 싶은 말맛, 20~30대 반응 좋음 | "사정"의 중의성 | 2순위 |
| 3 | **한 푼 사주** | 소액·친근 | "한 푼"이 소비·절약 뉘앙스와 맞음 | 사주 전문성 약하게 읽힘 | 후보 |
| 4 | **돈 나가는 날** | 부정 회피형 | 문제 제기형이라 클릭률 높음 | 앱이 부정적으로만 읽힘 | 후보 |
| 5 | **재물신 리포트** | 권위형 | 40~50대 신뢰 | 20대에 무겁고, "신"의 종교성 논란 소지 | 후보 |

- **최종 제안: `오늘 지갑운`** (부제: "생년월일로 보는 오늘의 돈 씀씀이"). 콘솔 등록 시 이름 중복 여부를 먼저 확인한다.
- 이름에 **"로또"·"복권"·"당첨"·"투자"** 를 넣지 않는다(수익 상품·금융 상품으로 오인될 소지, 심사 리스크).

### 1.6 브랜드 톤 — 말투 규칙

| 규칙 | 내용 | 예시 |
|---|---|---|
| 반말·직설 | 존댓말 금지, 한 문장 25자 이내 | "오늘 카드 내려놔라." |
| 숫자로 말한다 | 감정 형용사 대신 수치·시간·개수 | "21~23시 사이 결제 1건이면 47점." |
| 명령은 하나만 | 한 화면에 행동 지시는 최대 1개 | "편의점만 가라. 온라인은 내일." |
| 겁주지 않는다 | 저주·불안 조장 금지(심사·리텐션 모두 손해) | ✗ "큰돈 잃는다" → ○ "오늘은 새는 날이다" |
| 면책은 고정 | 결과 하단 고정 문구 | "재미로 보는 명리 콘텐츠입니다. 금융·투자 자문이 아닙니다." |

### S1. 온보딩 / 입력 — "3탭, 15초"

```
┌─────────────────────────────────────┐
│  (Safe Area: 상태바/Dynamic Island)  │
│                              ✕ 닫기  │  ← 앱인토스 네비게이션 바
├─────────────────────────────────────┤
│                                     │
│      오늘 지갑운                     │
│      생년월일만 넣으면 오늘 돈       │
│      씀씀이를 계산해준다.            │
│                                     │
│      ┌───────────────────────────┐  │
│      │  1993  .  09  .  13       │  │  ← 숫자 키패드 자동
│      └───────────────────────────┘  │
│                                     │
│      [ 양력 ● ]   [ 음력 ○ ]        │
│                                     │
│      태어난 시간  [ 모름 ▾ ]  (선택) │  ← 기본값 '모름'
│                                     │
│      ┌───────────────────────────┐  │
│      │      내 지갑 점수 보기     │  │  ← 1차 CTA
│      └───────────────────────────┘  │
│                                     │
│      로그인 없이 바로 됩니다.        │
│      재미로 보는 콘텐츠 · 금융자문 ✗ │
└─────────────────────────────────────┘
```

**동작 명세**

| 요소 | 규칙 |
|---|---|
| 날짜 입력 | 3개 숫자 필드, 자동 포커스 이동. 1900~현재만 허용. 유효성 실패 시 버튼 비활성 + 인라인 사유("태어난 연도를 확인해줘") |
| 양/음력 | 기본 양력. 음력 선택 시 윤달 체크박스 노출(음력 12월·윤달 처리) |
| 시간 | `모름` 기본. 선택 시 12지지 라벨("오시 11:30~13:29")로 보조 표기 → 사주 용어를 몰라도 선택 가능 |
| 저장 | `User.getAnonymousKey()`로 받은 hash + 입력값을 로컬(`Storage.setItem('wallet_profile')`)에 저장. 서버 저장 시 생년월일시는 암호화 컬럼 |
| 재방문 | 로컬 프로필 존재 시 **S1을 건너뛰고 S2 직행**(원탭). S2 상단에 "내 생일 변경" 텍스트 버튼으로만 수정 경로 제공 |
| 로딩 | 번들 안의 60갑자 테이블로 **클라이언트 계산**(서버 왕복 0) → 체감 200ms 이내. 로딩 스피너 대신 즉시 결과 |
| 로그인/알림 | **이 화면에 없음**. 토스 로그인은 이 앱에서 사용하지 않음(익명키로 충분) |

**예외 처리**
- 음력→양력 변환 실패(범위 밖): "음력 1900~2100년만 지원해. 양력으로 다시 넣어줘."
- 이미 오늘 결과를 본 사용자가 프로필을 바꾸면: 새 결과로 갱신하되 "잠금 해제 상태는 당일 1회만" 규칙 유지(2회차부터는 잠금 다시 걸림 → 어뷰징 방지).

## 3. 수익화 시뮬레이션 & 광고/결제 배치표

### 3.1 수수료 구조 (실제 정산 기준)

**인앱광고(IAA)** — 두 단계로 깎인다.

| 단계 | 공제 | 예: 광고 매출 10,000원 |
|---|---|---:|
| 운영비(미디에이션·Toss Ads) | 약 30% | -3,000 → 광고 수익 7,000 |
| 앱인토스 수수료 | 광고 수익의 15% (+수수료 부가세) | -1,050 -105 → 5,845 |
| 광고 수익 부가세 | 10% (정산금과 함께 지급) | +700 |
| **파트너 입금** | **≈ 광고 매출의 65%** | **6,545원** |

- 순수익(부가세 제외)은 **광고 매출의 59.5%**.
- **정산은 월 단위, 정산금이 5,000원 이하면 이월**된다(익월 말일 입금).

**인앱결제(IAP)**

| 경로 | 수수료 | 11,000원 결제 시 입금 |
|---|---|---:|
| 애플 | 앱마켓 15% + 토스 5% (+부가세) | 8,745원 (79.5%) |
| 구글 | 앱마켓 15% + 토스 5% (+부가세) | 8,895원 (80.9%) |

- 앱마켓 15%는 **매출이 커지면 30%로 변경될 수 있다**(현재 15% 적용). 30%가 되면 실효 수익은 66% 수준으로 떨어지므로 시나리오에 민감도 표시.
- 사업자 등록: **인앱광고는 누적 예상수익 5,000원 미만까지 유예** 가능(5,000원 도달 시 5영업일 내 등록, 미등록 시 노출 중단). **인앱결제는 사업자 등록 필수**.

**절대 금지 목록** (위반 시 30일 이용 제한·영구 제한 가능)
- 광고를 콘텐츠로 위장("추천 서비스", "금융 팁" 라벨), "Ad" 표기 제거

- 운영용 광고 ID로 테스트(반드시 테스트 ID 사용)

## 4. 사주·운세 생성 로직 설계

### 4.1 파이프라인

```
입력(생년월일 [+시], 양/음력)
   │
   ├─(1) 음력→양력 변환 (1900~2100 테이블)
   ├─(2) 만세력: 년주·월주(절기 기준)·일주·시주 → 4기둥 8자
   │
   ├─(3) 오행 분포(천간 8 + 지지 장간 가중)
   ├─(4) 오늘의 일진(60갑자) + 월운·세운
   │
   ├─(5) 일간 ↔ 오늘 천간: 십성(10종) 판정
   ├─(6) 오행 관계: 상생·상극·비화 / 지지 관계: 충·합·형·해
   ├─(7) 점수화 → 지갑 점수·소비 방어력·재물 등급
   ├─(8) 시간대·색·아이템·번호 (seed 기반 결정적 생성)
   └─(9) 템플릿 조합 → 직설 코멘트 (LLM 없이)
```

### 4.2 만세력 계산

| 항목 | 규칙 | 구현 |
|---|---|---|
| 일진(日辰) | 60갑자가 하루 1개씩 순환. 자정(00:00) 기준 | 기준일 앵커 + `(날짜차이 mod 60)` |
| 년주 | **입춘** 기준으로 바뀜(양력 1/1 아님) | 절기 시각 테이블 필요 |
| 월주 | 24절기(입춘·경칩·청명…) 기준. 양력 월과 다름 | 절기 시각 테이블(연도별 12~24개) |
| 시주 | 12지지 2시간 단위, 자시 23:30~01:29 | 시각 → 지지 인덱스 |
| 음력 변환 | 1900~2100 음양력 테이블 | 오프라인 번들(외부 API 의존 금지) |

- **검증 앵커(실측 대조 완료)**
  - `2026-11-20` → 병오년 · 기해월 · **무술(戊戌)일**
  - `1993-09-13` → 계유년 · 신유월 · **정유(丁酉)일**
- 위 두 값은 공개 만세력 3곳(사자사주·Mythelo·금여만세력)에서 동일하게 확인됨. **출시 전 30건 이상을 한국천문연구원 만세력과 대조**한다(특히 입춘 전후·윤달·자시 경계 3종을 반드시 포함).

| 정인(正印) | 보호·문서·지원 | +3 |

**5) 소비 방어력 / 충동구매 위험 시간대**

```ts
충동지수 = 40
  + (상관이면 8) + (겁재면 12) + (편재면 10)

  + (사주 火·水 과다 보정 0~10)
방어력 = clamp(100 - 충동지수, 5, 95)
```

| 인(寅) | 03:30~05:29 | 신(申) | 15:30~17:29 |
| 묘(卯) | 05:30~07:29 | 유(酉) | 17:30~19:29 |
| 진(辰) | 07:30~09:29 | 술(戌) | 19:30~21:29 |
| 사(巳) | 09:30~11:29 | 해(亥) | 21:30~23:29 |

**6) 계산 예시 (계산 검증용 입력)**

| 항목 | 값 |
|---|---|
| 사주 | 계유년 · 신유월 · **정유일** (일간 丁火) |
| 오늘(2026-11-20) | **무술(戊戌)일** — 천간 戊(陽土), 지지 戌(土) |
| 십성(천간) | 정화 → 무토 = **상관(傷官) +2** |
| 오행 관계 | 火生土 = 설기(泄氣) **-4** |
| 지장간(戌: 戊·辛·丁) | 상관+2, 편재+12, 비견-5 → 평균 3 → **+1.8** |

| 합계 | 50 + 2 - 4 + 1.8 - 5 = **44.8 → 45점** |
| 등급 | "흔들리는 날" / 하위 38% |
| 방어력 | 충동지수 53(상관 8 + 편재 지장간 5) → **47%** |
| 위험 시간대 | 戌과 충=辰(07:30~09:29), 해=酉(17:30~19:29) |
| 기회 시간 | 戌과 육합=卯(05:30~07:29) |

### 4.4 색·아이템·번호 생성 (결정적)

```ts
seed = hash(anonKey + birthYMD + todayISO)   // 같은 날 같은 사람 = 같은 결과
```

| 오행 | 럭키 컬러 | 럭키 아이템(예시 풀) |
|---|---|---|
| 木 | 청록·연두 | 나무 소재 소품, 초록 지갑, 화분 |
| 火 | 붉은·주황 | 가죽 카드지갑, 향초, 빨간 펜 |
| 土 | 노랑·베이지 | 황토색 파우치, 도자기 머그, 손수건 |
| 金 | 흰색·은색 | 손목시계, 동전 1개, 금속 명함케이스 |
| 水 | 검정·남색 | 검은 우산, 물병, 남색 노트 |

- 행운 번호 6개: `seed`로 Fisher–Yates 셔플 → 1~45 중 6개 (보너스 1개는 옵션). **`Math.random` 금지**(새로고침 조작 방지·재현성 확보).
- 표기: "행운 번호 6개 · 재미용, 구매를 권하지 않습니다" 를 카드 안에 상시 노출.

### 4.5 코멘트 생성 — 템플릿 트리 (MVP) / LLM(Phase 2)

**구조**: `등급 × 주된 십성 × 시간대 × 요일` 4축 조합.

```
[등급 슬롯]  (6)     예: "새는 날"
[원인 슬롯]  (10)    예: "상관이 붙어서 씀씀이가 커졌다"
[지시 슬롯]  (12)    예: "카드는 집에 두고 현금 3만 원만 들고 나가라"
[마감 슬롯]  (8)     예: "21시 넘으면 앱 결제는 무조건 다음 날로."
```

- 조합 수: 6 × 10 × 12 × 8 = **5,760가지**. 실제 사용은 등급·원인·지시의 **호환 규칙**으로 800~1,200개 문장 풀을 만들어 중복 체감을 없앤다.
- **품질 규칙**: ① 모든 문장은 행동으로 끝난다 ② 금액·시간·개수 중 최소 1개를 포함한다 ③ 같은 사용자가 7일 내 같은 문장을 두 번 보지 않는다(사용 이력으로 회피).
- **LLM은 MVP에서 쓰지 않는다.** 이유: ①결과 지연·비용 ②환각으로 금지 표현(종목·수익 보장)이 섞일 위험 ③심사 재현성. Phase 2에서 "하루 1회 전체 유저 공통 코멘트 배치 생성 + 사람 검수 후 배포" 형태로만 도입.

**문장 예시 (톤 검증용)**

| 점수 | 문장 |
|---:|---|

```bash
npm install @apps-in-toss/web-framework
npx ait init
npm install @toss/tds-mobile @toss/tds-mobile-ait @emotion/react@^11 react@^18 react-dom@^18
```

// apps-in-toss.config.ts
import { defineConfig } from '@apps-in-toss/web-framework/config';

export default defineConfig({

| 이벤트(`log_name`) | 시점 | 파라미터 |
|---|---|---|
| `s1_input_start` | 날짜 입력 시작 | `source` |
| `s2_result_view` | 결과 화면 표시 | `score_band`, `has_birth_time` |

### 6.1 검수 체크리스트 (출시 요청 전 전부 ☑)

**접속·네비게이션**
- ☐ 미니앱 정상 실행, 콜드 스타트 10초 이내
- ☐ 앱인토스 네비게이션 바 사용, 뒤로가기 전 화면 정상 동작
- ☐ 최초 화면 뒤로가기 → 미니앱 종료
- ☐ 닫기 버튼 항상 존재, 자체 뒤로가기와 중복 노출 없음
- ☐ Safe Area 준수(iOS 상단·하단 잘림 없음)

**UX·다크패턴**
- ☐ 진입 즉시 바텀시트 없음(로그인·알림·권한)
- ☐ 모든 화면에서 이탈 경로 명확(막다른 화면 0)
- ☐ CTA 문구만 보고 다음 행동 예측 가능
- ☐ 자사 서비스·앱 설치 유도 0
- ☐ 광고를 예상 못 하는 순간에 노출하지 않음
- ☐ 임시 문구·샘플 이미지·로렘입숨 0

**광고**
- ☐ 모든 광고가 사전 로딩되어 재생 시점에 실시간 로딩 없음
- ☐ 전면광고 직전 고지 문구/아이콘 노출
- ☐ 리워드 1회 시청 후 추가 광고 없이 결과 표시
- ☐ 리워드 완주 시 보상 정상 지급, 중도 이탈 시 미지급 + 재시도 가능
- ☐ 배너는 스크롤 화면에만, "Ad" 표기 유지, 화면당 1개
- ☐ 테스트 ID가 아닌 실제 광고 ID로 최종 확인
- ☐ 광고 종료 후 미니앱 화면 복귀 정상

**결제**
- ☐ 주문 금액과 마켓 결제창 금액 일치
- ☐ 결제 완료 후 복귀 시 권한 반영(광고 제거 즉시 적용)
- ☐ 결제 취소 시 주문 화면 복귀
- ☐ 실패 사유 사용자 인지 가능
- ☐ 결제 내역 화면 제공
- ☐ 미결 주문 복구(`getPendingOrders`) 동작
- ☐ 기기 변경 후에도 구매 데이터 유지

**콘텐츠·정책**
- ☐ 결과 화면 하단 면책 문구 상시 노출
- ☐ 금지어 스캔 0건(종목·매수·매도·보장·당첨·확률·대출·보증)
- ☐ 로또 번호 카드에 "구매 권유 아님" 표기
- ☐ 만세력 대조 30건 오차 0
- ☐ 같은 입력·같은 날 = 같은 결과
- ☐ 개인정보(생년월일) 로그 전송 0

**성능·안정성**
- ☐ 인터랙션 지연 2초 미만
- ☐ 네트워크 차단 상태에서도 무료 결과 표시(오프라인 계산)

- ☐ HTTPS 통신만 사용

### 6.2 출시 절차

1. **앱 등록** — 콘솔에서 앱 이름(`오늘 지갑운`), 카테고리(운세/사주), 앱 소개, 스크린샷 5장, OG 이미지 등록. 소개 첫 문장에 "금융 자문 아님" 명시.
2. **사업자·정산** — 광고만 먼저 시작하면 누적 5,000원까지 유예 가능. 결제를 붙이려면 개인사업자 등록 + 정산 정보(검토 영업일 2~3일) 필요. **업종과 서비스 업종이 일치해야 함**(정보통신업/콘텐츠 제공).
3. **광고 그룹 생성** — `S2_배너`, `S2S3_전면`, `S3_리워드` 3개. 리워드 보상 명칭("잠금 해제 3종")을 화면 용어와 동일하게 입력. 광고 그룹 ID 발급 후 최대 2시간 지연 가능.
4. **상품 등록** — `calendar_365` / `no_ads` / `monthly_report`, 이미지 1024×1024.
5. **테스트** — SDK 3.x는 샌드박스 미지원 → devtools mock으로 흐름 확인 후 **콘솔 QR로 토스 앱 실기기 테스트**(QR 테스트는 실제 결제로 처리됨). iOS ATT 거부 상태에서도 광고 로드/대체 동작 확인.
6. **출시 요청 → 검수** — 반려 시 사유별 수정(대부분 광고 고지·바텀시트·링크 유도).
7. **출시 후** — D+2주 데이터로 **추천 미니앱 신청**(UX 5원칙 + 재방문율 + 리뷰 + 성능 4기준). 부스팅 선정 시 노출 약 20배.
